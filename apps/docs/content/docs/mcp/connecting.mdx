The SDK provides the `MCPClient` class for connecting to MCP servers. You can use it directly for full control, or through React hooks for automatic lifecycle management.

## Direct Client Usage

For non-React environments or when you need full control over the connection:

```typescript
import { createMCPClient } from '@yourgpt/copilot-sdk/mcp';

const client = createMCPClient({
  name: "github",
  transport: "http",
  url: "https://mcp.github.com",
  headers: { Authorization: `Bearer ${token}` },
  timeout: 30000,
});

// Connect to the server
await client.connect();

// Get available tools
const tools = client.getTools();
console.log(`${tools.length} tools available`);

// Call a tool
const result = await client.callTool("create_issue", {
  title: "Bug report",
  body: "Found an issue...",
});

// Convert to ToolDefinitions for CopilotProvider
const toolDefinitions = client.toToolDefinitions();

// Disconnect when done
await client.disconnect();
```

## Transport Types

### HTTP Transport (Recommended)

The HTTP transport uses the streamable HTTP protocol, which is the recommended way to connect to remote MCP servers.

```typescript
import { createMCPClient } from '@yourgpt/copilot-sdk/mcp';

const client = createMCPClient({
  name: "github",
  transport: "http",
  url: "https://mcp.github.com",
  headers: {
    Authorization: `Bearer ${process.env.GITHUB_TOKEN}`,
    "X-Custom-Header": "value",
  },
  timeout: 30000, // 30 second timeout
});

await client.connect();
```

**Configuration Options:**

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `name` | `string` | Required | Unique identifier for this connection |
| `transport` | `"http"` | Required | Transport type |
| `url` | `string` | Required | Server endpoint URL |
| `headers` | `Record<string, string>` | `{}` | Custom HTTP headers |
| `timeout` | `number` | `30000` | Request timeout in milliseconds |

### SSE Transport

Server-Sent Events transport for servers that stream responses in real-time.

```typescript
const client = createMCPClient({
  name: "realtime",
  transport: "sse",
  url: "https://mcp.example.com/events",
  headers: { Authorization: `Bearer ${token}` },
});

await client.connect();
```

### Stdio Transport (Coming Soon)

For local MCP servers that communicate via stdin/stdout:

```typescript
const client = createMCPClient({
  name: "filesystem",
  transport: "stdio",
  command: "npx",
  args: ["-y", "@anthropic/filesystem-mcp-server"],
  env: { HOME: process.env.HOME },
  cwd: process.cwd(),
});

await client.connect();
```

<Callout type="warning">
  Stdio transport is not yet implemented. Use HTTP or SSE transport for now.
</Callout>

## Connection Lifecycle

The MCP client follows a specific connection lifecycle:

```
disconnected ──▶ connecting ──▶ connected
                     │              │
                     │              │
                     ▼              ▼
                   error      disconnected
```

### Connection States

| State | Description |
|-------|-------------|
| `disconnected` | Not connected to the server |
| `connecting` | Connection in progress |
| `connected` | Successfully connected and tools are available |
| `error` | Connection failed or error occurred |

### Monitoring Connection State

```typescript
const client = createMCPClient(config, {
  onConnectionStateChange: (state) => {
    console.log(`Connection state: ${state}`);

    if (state === "connected") {
      console.log("Ready to use MCP tools!");
    } else if (state === "error") {
      console.error("Connection failed");
    }
  },
  onError: (error) => {
    console.error("MCP error:", error.message);
  },
});
```

## Event Handlers

The client supports several event handlers for monitoring activity:

```typescript
const client = createMCPClient(config, {
  // Connection state changes
  onConnectionStateChange: (state) => {
    console.log(`State: ${state}`);
  },

  // Tools list updated (e.g., server notified of changes)
  onToolsChange: (tools) => {
    console.log(`Tools updated: ${tools.length} available`);
  },

  // Elicitation request from server (human-in-the-loop)
  onElicitationRequest: async (request) => {
    // Show approval UI to user
    const approved = await showApprovalDialog(request);
    return {
      requestId: request.requestId,
      accepted: approved,
      data: approved ? request.defaults : undefined,
    };
  },

  // Error occurred
  onError: (error) => {
    console.error("Error:", error);
  },

  // Server notification received
  onNotification: (method, params) => {
    console.log(`Notification: ${method}`, params);
  },
});
```

## Error Handling

Handle connection and tool call errors gracefully:

```typescript
import { createMCPClient, MCPError } from '@yourgpt/copilot-sdk/mcp';

const client = createMCPClient(config);

try {
  await client.connect();
} catch (error) {
  if (error instanceof MCPError) {
    console.error(`MCP Error (${error.code}): ${error.message}`);
    // Handle specific error codes
    if (error.code === -32600) {
      console.error("Invalid request - check your configuration");
    }
  } else {
    console.error("Unexpected error:", error);
  }
}

// Tool call error handling
try {
  const result = await client.callTool("risky_operation", { data: "value" });

  if (result.isError) {
    console.error("Tool returned an error:", result.content);
  } else {
    console.log("Success:", result.content);
  }
} catch (error) {
  console.error("Tool call failed:", error);
}
```

### Common Error Codes

| Code | Name | Description |
|------|------|-------------|
| `-32700` | Parse Error | Invalid JSON |
| `-32600` | Invalid Request | Request is not valid |
| `-32601` | Method Not Found | Tool or method doesn't exist |
| `-32602` | Invalid Params | Invalid arguments |
| `-32603` | Internal Error | Server-side error |

## Session Management

The MCP client maintains a session with the server. Here's how to manage it:

### Reconnection

```typescript
// Check connection and reconnect if needed
if (!client.isConnected()) {
  await client.connect();
}

// Ping to verify connection is alive
const isAlive = await client.ping();
if (!isAlive) {
  await client.disconnect();
  await client.connect();
}
```

### Refresh Tools

If the server's tools change, refresh the list:

```typescript
// Manually refresh tools
const updatedTools = await client.refreshTools();
console.log(`Now have ${updatedTools.length} tools`);
```

### Graceful Shutdown

```typescript
// Disconnect cleanly
await client.disconnect();

// In React, this is handled automatically by hooks
```

## Server Information

After connecting, you can access server metadata:

```typescript
await client.connect();

// Get server info
const serverInfo = client.getServerInfo();
console.log(`Connected to: ${serverInfo?.name} v${serverInfo?.version}`);

// Get server capabilities
const capabilities = client.getServerCapabilities();
if (capabilities?.tools?.listChanged) {
  console.log("Server supports dynamic tool updates");
}
```

## Converting Tools for CopilotProvider

To use MCP tools with the CopilotProvider, convert them to `ToolDefinition` format:

```typescript
// Convert with server prefix (recommended for multi-server setups)
const tools = client.toToolDefinitions({
  prefixToolNames: true,  // Tools named: github_create_issue
});

// Convert without prefix (single server)
const tools = client.toToolDefinitions({
  prefixToolNames: false,  // Tools named: create_issue
});

// Mark as server-side tools (executed remotely)
const tools = client.toToolDefinitions({
  serverLocation: true,  // Tools marked as server-side
});
```

<Callout type="info">
  When using React hooks like `useMCPTools`, this conversion happens automatically and tools are registered with CopilotProvider.
</Callout>
