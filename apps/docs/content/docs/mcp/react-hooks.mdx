The SDK provides three React hooks for MCP integration, each designed for different use cases.

## useMCPTools

The recommended hook for most use cases. It manages the MCP client connection and automatically registers tools with the CopilotProvider.

```tsx
import { useMCPTools } from '@yourgpt/copilot-sdk/react';

function GitHubIntegration() {
  const {
    state,
    isConnected,
    isLoading,
    toolDefinitions,
    connect,
    disconnect,
    callTool,
    refreshTools,
  } = useMCPTools({
    name: "github",
    transport: "http",
    url: "https://mcp.github.com",
    headers: { Authorization: `Bearer ${token}` },
    autoConnect: true,
    prefixToolNames: true,
    autoRegister: true,
  });

  if (isLoading) return <div>Connecting to GitHub...</div>;

  if (!isConnected) {
    return <button onClick={connect}>Connect to GitHub</button>;
  }

  return (
    <div>
      <p>Connected! {toolDefinitions.length} tools available</p>
      <ul>
        {toolDefinitions.map((tool) => (
          <li key={tool.name}>{tool.name}</li>
        ))}
      </ul>
      <button onClick={disconnect}>Disconnect</button>
    </div>
  );
}
```

### Configuration Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `name` | `string` | Required | Unique identifier for this connection |
| `transport` | `"http" \| "sse" \| "stdio"` | Required | Transport type |
| `url` | `string` | - | Server URL (required for http/sse) |
| `headers` | `Record<string, string>` | `{}` | Custom HTTP headers |
| `timeout` | `number` | `30000` | Request timeout in ms |
| `autoConnect` | `boolean` | `true` | Connect automatically on mount |
| `prefixToolNames` | `boolean` | `true` | Prefix tool names with client name |
| `autoRegister` | `boolean` | `true` | Auto-register tools with CopilotProvider |
| `onConnectionStateChange` | `(state) => void` | - | Connection state callback |
| `onToolsChange` | `(tools) => void` | - | Tools updated callback |
| `onElicitationRequest` | `async (req) => response` | - | Handle elicitation requests |
| `onError` | `(error) => void` | - | Error callback |

### Return Values

| Property | Type | Description |
|----------|------|-------------|
| `state` | `MCPClientState` | Current client state |
| `isConnected` | `boolean` | Whether client is connected |
| `isLoading` | `boolean` | Whether connection is in progress |
| `toolDefinitions` | `ToolDefinition[]` | Converted tool definitions |
| `connect` | `() => Promise<void>` | Connect to server |
| `disconnect` | `() => Promise<void>` | Disconnect from server |
| `callTool` | `(name, args) => Promise<result>` | Call a tool directly |
| `refreshTools` | `() => Promise<tools>` | Refresh tools list |

## useMCPClient

A lower-level hook that provides MCP client management without automatic tool registration. Use this when you need more control.

```tsx
import { useMCPClient } from '@yourgpt/copilot-sdk/react';

function ManualToolRegistration() {
  const { state, isConnected, connect, callTool } = useMCPClient({
    name: "custom-server",
    transport: "http",
    url: "https://mcp.example.com",
    autoConnect: false,
  });

  const handleConnect = async () => {
    await connect();
    // Manually handle tools after connection
    console.log("Tools:", state.tools);
  };

  return (
    <div>
      <p>Status: {state.connectionState}</p>
      {!isConnected && (
        <button onClick={handleConnect}>Connect</button>
      )}
    </div>
  );
}
```

### When to Use useMCPClient

- You need to manually manage tool registration
- You're building custom tool handling logic
- You want to process tools before registration
- You're using MCP outside of CopilotProvider

## useMCPUIIntents

Hook for handling intents from MCP-UI interactive components. Use this when MCP tools return UI that can trigger actions.

```tsx
import { useMCPUIIntents } from '@yourgpt/copilot-sdk/react';
import { useCopilotChat } from '@yourgpt/copilot-sdk/react';

function ChatWithMCPUI() {
  const { sendMessage } = useCopilotChat();

  const { handleIntent } = useMCPUIIntents({
    // Handle tool calls from UI components
    onToolCall: async (name, args, context) => {
      console.log(`Calling tool: ${name}`, args);
      // Tool calls are typically handled automatically
    },

    // Handle semantic actions
    onIntent: (action, data, context) => {
      if (action === "add_to_cart") {
        addToCart(data?.productId, data?.quantity);
      } else if (action === "select_variant") {
        setSelectedVariant(data?.variantId);
      }
    },

    // Pre-fill the chat input
    onPrompt: (text, context) => {
      setInputValue(text);
    },

    // Show notifications/toasts
    onNotify: (message, level, context) => {
      toast({ message, type: level || "info" });
    },

    // Handle link clicks
    onLink: (url, newTab, context) => {
      // Return false to prevent default behavior
      if (url.startsWith("app://")) {
        navigate(url.replace("app://", "/"));
        return false;
      }
      // Return undefined/true for default behavior
    },
  });

  return (
    <CopilotChat
      onUIIntent={handleIntent}
    />
  );
}
```

### Intent Types

| Intent Type | Handler | Description |
|-------------|---------|-------------|
| `tool` | `onToolCall` | Call another MCP tool |
| `intent` | `onIntent` | Semantic action for app to interpret |
| `prompt` | `onPrompt` | Add text to chat input |
| `notify` | `onNotify` | Show notification/toast |
| `link` | `onLink` | Open a URL |

### Configuration Options

| Option | Type | Description |
|--------|------|-------------|
| `onToolCall` | `(name, args?, context?) => void \| Promise` | Handle tool call intents |
| `onIntent` | `(action, data?, context?) => void \| Promise` | Handle semantic action intents |
| `onPrompt` | `(text, context?) => void` | Handle prompt intents |
| `onNotify` | `(message, level?, context?) => void` | Handle notification intents |
| `onLink` | `(url, newTab?, context?) => boolean \| void` | Handle link intents |
| `requireConsent` | `{ tool?: boolean; link?: boolean }` | Require user consent |

## Multiple MCP Servers

Use multiple `useMCPTools` hooks to connect to multiple servers simultaneously:

```tsx
function MultiServerCopilot() {
  const github = useMCPTools({
    name: "github",
    transport: "http",
    url: "https://mcp.github.com",
    headers: { Authorization: `Bearer ${githubToken}` },
  });

  const slack = useMCPTools({
    name: "slack",
    transport: "http",
    url: "https://mcp.slack.com",
    headers: { Authorization: `Bearer ${slackToken}` },
  });

  const filesystem = useMCPTools({
    name: "fs",
    transport: "http",
    url: "http://localhost:8080/mcp",
  });

  const allConnected = github.isConnected && slack.isConnected && filesystem.isConnected;
  const totalTools =
    github.toolDefinitions.length +
    slack.toolDefinitions.length +
    filesystem.toolDefinitions.length;

  return (
    <div>
      <div>
        GitHub: {github.isConnected ? "Connected" : "Disconnected"}
        ({github.toolDefinitions.length} tools)
      </div>
      <div>
        Slack: {slack.isConnected ? "Connected" : "Disconnected"}
        ({slack.toolDefinitions.length} tools)
      </div>
      <div>
        Filesystem: {filesystem.isConnected ? "Connected" : "Disconnected"}
        ({filesystem.toolDefinitions.length} tools)
      </div>

      {allConnected && (
        <p>{totalTools} tools available across all servers</p>
      )}

      <CopilotChat />
    </div>
  );
}
```

<Callout type="info">
  When using multiple servers with `prefixToolNames: true` (default), tools are namespaced automatically:
  - `github_create_issue`
  - `slack_send_message`
  - `fs_read_file`
</Callout>

## Handling Elicitation

Elicitation allows MCP servers to request user input during tool execution:

```tsx
function CopilotWithApproval() {
  const [pendingRequest, setPendingRequest] = useState(null);

  const { isConnected } = useMCPTools({
    name: "dangerous-ops",
    transport: "http",
    url: "https://mcp.dangerous.com",
    onElicitationRequest: async (request) => {
      // Store request and wait for user decision
      return new Promise((resolve) => {
        setPendingRequest({
          request,
          resolve,
        });
      });
    },
  });

  const handleApprove = (data) => {
    pendingRequest.resolve({
      requestId: pendingRequest.request.requestId,
      accepted: true,
      data,
    });
    setPendingRequest(null);
  };

  const handleReject = (reason) => {
    pendingRequest.resolve({
      requestId: pendingRequest.request.requestId,
      accepted: false,
      reason,
    });
    setPendingRequest(null);
  };

  return (
    <>
      <CopilotChat />

      {pendingRequest && (
        <ApprovalDialog
          request={pendingRequest.request}
          onApprove={handleApprove}
          onReject={handleReject}
        />
      )}
    </>
  );
}
```

## Best Practices

### 1. Use Prefixed Tool Names

When connecting to multiple servers, keep `prefixToolNames: true` to avoid naming conflicts:

```tsx
// Good: Tools are namespaced
useMCPTools({ name: "github", prefixToolNames: true });
// Results in: github_create_issue, github_list_repos

// Risky: May conflict with other servers
useMCPTools({ name: "github", prefixToolNames: false });
// Results in: create_issue, list_repos
```

### 2. Handle Connection Errors

Always handle potential connection failures:

```tsx
const { isConnected, state } = useMCPTools({
  name: "server",
  transport: "http",
  url: "https://mcp.example.com",
  onError: (error) => {
    toast.error(`MCP Error: ${error.message}`);
  },
});

// Check for error state
if (state.connectionState === "error") {
  return <div>Connection failed: {state.error}</div>;
}
```

### 3. Clean Up on Unmount

The hooks automatically disconnect on unmount, but ensure your component handles the loading/disconnected states:

```tsx
function SafeMCPComponent() {
  const { isConnected, isLoading } = useMCPTools(config);

  // Don't render sensitive content until connected
  if (isLoading) return <Spinner />;
  if (!isConnected) return <ConnectionError />;

  return <ConnectedContent />;
}
```
