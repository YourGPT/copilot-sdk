## Multi-Server Management

For applications connecting to multiple MCP servers, use the `MCPClientManager` class for centralized management.

```typescript
import { createMCPClientManager } from '@yourgpt/copilot-sdk/mcp';

const manager = createMCPClientManager([
  {
    name: "github",
    transport: "http",
    url: "https://mcp.github.com",
    headers: { Authorization: `Bearer ${githubToken}` },
  },
  {
    name: "slack",
    transport: "http",
    url: "https://mcp.slack.com",
    headers: { Authorization: `Bearer ${slackToken}` },
  },
  {
    name: "database",
    transport: "http",
    url: "http://localhost:8080/mcp",
  },
], {
  // Manager-level events
  onConnectionStateChange: (clientName, state) => {
    console.log(`${clientName}: ${state}`);
  },
  onToolsChange: (clientName, tools) => {
    console.log(`${clientName}: ${tools.length} tools`);
  },
  onError: (clientName, error) => {
    console.error(`${clientName} error:`, error);
  },
  onAllConnected: () => {
    console.log("All MCP servers connected!");
  },
  onAllDisconnected: () => {
    console.log("All MCP servers disconnected");
  },
});

// Connect all servers
await manager.connectAll();

// Get aggregated state
const state = manager.getState();
console.log(`Total tools: ${state.totalToolCount}`);
console.log(`All connected: ${state.allConnected}`);

// Get all tool definitions (with prefixes)
const allTools = manager.getAllToolDefinitions();
// => github_create_issue, slack_send_message, database_query, ...

// Call a tool on a specific server
const result = await manager.callTool("github", "create_issue", {
  title: "Bug report",
});

// Disconnect all
await manager.disconnectAll();
```

### Manager State

The manager provides aggregated state:

```typescript
interface MCPClientManagerState {
  // Individual client states
  clients: Record<string, MCPClientState>;
  // All tools from all connected clients
  allTools: MCPToolDefinition[];
  // Whether all enabled clients are connected
  allConnected: boolean;
  // Whether any client is connecting
  anyConnecting: boolean;
  // Whether any client has an error
  anyError: boolean;
  // Total number of tools
  totalToolCount: number;
}
```

## Tool Prefixing Strategies

When connecting to multiple servers, tool naming conflicts can occur. Here are strategies to handle them:

### Server Prefix (Recommended)

The default behavior prefixes tool names with the client name:

```typescript
// With prefixToolNames: true (default)
useMCPTools({ name: "github", ... });
// Tools: github_create_issue, github_list_repos, ...

useMCPTools({ name: "slack", ... });
// Tools: slack_send_message, slack_list_channels, ...
```

### No Prefix (Single Server)

For single-server setups, you can disable prefixing:

```typescript
useMCPTools({
  name: "server",
  prefixToolNames: false,
  // ...
});
// Tools: create_issue, list_repos, ...
```

### Custom Tool Adaptation

For full control, use the `MCPToolAdapter` directly:

```typescript
import { MCPToolAdapter } from '@yourgpt/copilot-sdk/mcp';

const adapter = new MCPToolAdapter("custom-prefix");

const customTools = mcpTools.map((tool) =>
  adapter.toToolDefinition(tool, {
    prefix: true,
    asServerTool: true,
    callTool: client.callTool.bind(client),
  })
);
```

## Tool Chaining

MCP-UI enables tool chaining where one tool's UI can trigger another tool:

```tsx
function ToolChainingExample() {
  const { callTool } = useMCPTools(config);

  const { handleIntent } = useMCPUIIntents({
    // Handle tool calls from UI
    onToolCall: async (name, args, context) => {
      console.log(`Chained tool call: ${name}`, args);

      // Call the tool
      const result = await callTool(name, args);

      // Optionally handle the result
      if (result.isError) {
        toast.error("Tool call failed");
      }

      return result;
    },
  });

  return <CopilotChat onUIIntent={handleIntent} />;
}
```

## Elicitation / Approval Flows

Elicitation allows MCP servers to request user input during tool execution. This is useful for sensitive operations requiring approval.

### Elicitation Request Types

| Mode | Description | Use Case |
|------|-------------|----------|
| `confirm` | Yes/No approval | "Delete this file?" |
| `select` | Choose from options | "Which environment?" |
| `form` | Fill out a form | Custom data entry |

### Implementing Elicitation

```tsx
function CopilotWithApproval() {
  const [pendingApproval, setPendingApproval] = useState(null);

  const { isConnected } = useMCPTools({
    name: "secure-ops",
    transport: "http",
    url: "https://mcp.secure.com",
    onElicitationRequest: async (request) => {
      return new Promise((resolve) => {
        setPendingApproval({
          request,
          resolve,
        });
      });
    },
  });

  // Approval Dialog
  const renderApprovalDialog = () => {
    if (!pendingApproval) return null;

    const { request, resolve } = pendingApproval;

    const handleApprove = (data) => {
      resolve({
        requestId: request.requestId,
        accepted: true,
        data,
      });
      setPendingApproval(null);
    };

    const handleReject = () => {
      resolve({
        requestId: request.requestId,
        accepted: false,
        reason: "User declined",
      });
      setPendingApproval(null);
    };

    switch (request.mode) {
      case "confirm":
        return (
          <ConfirmDialog
            message={request.message}
            onConfirm={() => handleApprove({})}
            onCancel={handleReject}
          />
        );

      case "select":
        return (
          <SelectDialog
            message={request.message}
            options={request.options}
            onSelect={(value) => handleApprove({ selected: value })}
            onCancel={handleReject}
          />
        );

      case "form":
        return (
          <FormDialog
            message={request.message}
            schema={request.schema}
            defaults={request.defaults}
            onSubmit={handleApprove}
            onCancel={handleReject}
          />
        );
    }
  };

  return (
    <>
      <CopilotChat />
      {renderApprovalDialog()}
    </>
  );
}
```

### Elicitation Request Structure

```typescript
interface MCPElicitationRequest {
  // Unique request ID
  requestId: string;
  // Elicitation mode
  mode: "form" | "confirm" | "select";
  // Message to display
  message?: string;
  // JSON Schema for form mode
  schema?: MCPToolInputSchema;
  // Options for select mode
  options?: MCPElicitationOption[];
  // Default values
  defaults?: Record<string, unknown>;
}

interface MCPElicitationResponse {
  requestId: string;
  accepted: boolean;
  data?: Record<string, unknown>;
  reason?: string;
}
```

## Server-Side Tool Execution

For sensitive tools, execute them on the server rather than the client:

```typescript
// Next.js API Route
// app/api/mcp/route.ts
import { createMCPClient } from '@yourgpt/copilot-sdk/mcp';

const mcpClient = createMCPClient({
  name: "sensitive-ops",
  transport: "http",
  url: process.env.MCP_SERVER_URL!,
  headers: { Authorization: `Bearer ${process.env.MCP_TOKEN}` },
});

export async function POST(req: Request) {
  const { toolName, args } = await req.json();

  // Validate and authorize
  if (!isAuthorized(req)) {
    return Response.json({ error: "Unauthorized" }, { status: 401 });
  }

  // Connect if needed
  if (!mcpClient.isConnected()) {
    await mcpClient.connect();
  }

  // Execute tool
  const result = await mcpClient.callTool(toolName, args);

  return Response.json(result);
}
```

Then call from the client:

```tsx
async function callServerTool(name: string, args: Record<string, unknown>) {
  const response = await fetch("/api/mcp", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ toolName: name, args }),
  });
  return response.json();
}
```

## Troubleshooting

### Connection Issues

**Problem**: Client stuck in "connecting" state

```typescript
// Add timeout handling
const CONNECT_TIMEOUT = 10000;

const connectWithTimeout = async () => {
  const timeoutPromise = new Promise((_, reject) =>
    setTimeout(() => reject(new Error("Connection timeout")), CONNECT_TIMEOUT)
  );

  try {
    await Promise.race([connect(), timeoutPromise]);
  } catch (error) {
    console.error("Connection failed:", error);
    // Handle timeout or error
  }
};
```

**Problem**: Frequent disconnections

```typescript
// Implement reconnection logic
useMCPTools({
  // ...config
  onConnectionStateChange: (state) => {
    if (state === "disconnected") {
      // Auto-reconnect after delay
      setTimeout(() => connect(), 3000);
    }
  },
  onError: (error) => {
    console.error("MCP Error:", error);
    // Log to monitoring service
  },
});
```

### Tool Execution Issues

**Problem**: Tool calls timing out

```typescript
// Increase timeout for slow tools
const client = createMCPClient({
  // ...config
  timeout: 60000, // 60 seconds
});
```

**Problem**: Invalid tool arguments

```typescript
// Validate arguments before calling
const toolSchema = client.getTools().find(t => t.name === "my_tool");

function validateArgs(args: unknown): boolean {
  // Validate against toolSchema.inputSchema
  return true; // or throw validation error
}

try {
  validateArgs(args);
  const result = await client.callTool("my_tool", args);
} catch (error) {
  console.error("Validation failed:", error);
}
```

### MCP-UI Issues

**Problem**: Intents not being received

```typescript
// Ensure postMessage is sent correctly from iframe
window.parent.postMessage({
  source: "mcp-ui",  // Important: include source
  intent: {
    type: "intent",
    action: "my_action",
    data: { key: "value" },
  },
}, "*");  // Use "*" or specific origin
```

**Problem**: Iframe security errors

```typescript
// Check sandbox permissions
<MCPUIFrame
  resource={resource}
  sandbox="allow-scripts allow-forms allow-same-origin"
/>
```

### Debug Mode

Enable verbose logging for debugging:

```typescript
// Add logging to events
const client = createMCPClient(config, {
  onConnectionStateChange: (state) => {
    console.log(`[MCP Debug] State: ${state}`);
  },
  onToolsChange: (tools) => {
    console.log(`[MCP Debug] Tools:`, tools.map(t => t.name));
  },
  onNotification: (method, params) => {
    console.log(`[MCP Debug] Notification: ${method}`, params);
  },
  onError: (error) => {
    console.error(`[MCP Debug] Error:`, error);
  },
});
```

## Protocol Versions

The SDK supports multiple MCP protocol versions:

| Version | Date | Features |
|---------|------|----------|
| `2025-06-18` | Latest | Full features |
| `2025-03-26` | - | Streamable HTTP |
| `2024-11-05` | Legacy | HTTP+SSE (deprecated) |

The SDK automatically negotiates the best supported version with the server.

```typescript
import { MCP_PROTOCOL_VERSION, SUPPORTED_PROTOCOL_VERSIONS } from '@yourgpt/copilot-sdk/mcp';

console.log(`Current: ${MCP_PROTOCOL_VERSION}`);
// => "2025-06-18"

console.log(`Supported: ${SUPPORTED_PROTOCOL_VERSIONS.join(", ")}`);
// => "2025-06-18, 2025-03-26, 2024-11-05"
```
